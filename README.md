# 장기요양 특화 프리미엄챗봇 · 사용자별 로컬 LLM

공용 사이트에 접속한 **각 사용자가 자신의 PC에 있는 Ollama**를 연결합니다. 운영자 서버의 공용 모델을 사용하는 방식이 아닙니다.

```text
공용 웹서버 → 사용자 브라우저에 23종 목록과 공개용 출력 항목 전달
사용자 브라우저 → 자신의 Ollama에 공개용 영어 JSON 안내·추가 설정·대화 전송 → 한국어 답변 표시
```

대화는 공용 서버를 거치지 않습니다. 사용자별 주소와 모델은 해당 브라우저의 localStorage에만 저장하고 대화는 IndexedDB에 저장합니다. 챗봇마다 여러 대화를 만들고 목록에서 이어갈 수 있습니다. 새로고침해도 대화가 유지되고 연결 변경·해제는 기록을 삭제하지 않습니다. 공유 PC에서는 기록 목록의 삭제 버튼으로 자신의 대화를 삭제하세요. 계정 기반 저장이나 사용자 로그인은 구현되어 있지 않습니다.

## 운영자: 웹사이트 실행

Node.js 22 이상. 외부 npm 패키지와 Ollama 설치가 웹서버에 필요하지 않습니다.

```sh
npm test
npm start
```

기본 HOST=127.0.0.1, PORT=3000. `.env.example`을 `.env`로 복사하고 `npm run start:local`을 실행하면 설정 파일을 읽습니다. 여러 사람이 이용하려면 HTTPS 도메인과 역방향 프록시를 준비하여 웹사이트를 배포합니다. 컨테이너 등에서 외부 바인딩이 필요한 경우 `HOST=0.0.0.0`으로 실행합니다. 클라우드의 loopback 주소는 사용자에게 공유할 사이트 주소가 아닙니다. 현재 외부 배포·도메인·HTTPS는 설정되지 않았습니다.

서버는 대화를 받는 `/api/chat`이나 운영자 모델 연결을 제공하지 않습니다. `OLLAMA_URL`, `OLLAMA_MODEL` 서버 환경변수도 사용하지 않습니다. 예전 환경 설정에 그 항목이 남아 있더라도 사용자 연결을 바꾸지 않습니다.

## 사용자: 자신의 Ollama 연결

1. 자기 PC에 [Ollama](https://ollama.com/download)를 설치합니다.
2. PC 성능에 맞는 모델을 준비합니다. 기본 입력값은 `qwen3:8b`입니다. 8B 모델과 긴 문맥도 메모리를 많이 사용할 수 있으므로 GPU·메모리 및 작성 품질을 실제 장비에서 확인하세요.

```sh
ollama pull qwen3:8b
```

3. Ollama가 **이 사이트의 정확한 origin(프로토콜+도메인+포트)** 에서 오는 요청을 허용하도록 `OLLAMA_ORIGINS`를 설정하고 Ollama를 완전히 종료 후 다시 실행합니다. 사이트의 ‘내 LLM 연결 → 설치·접속 허용 안내’에서 실제 접속 origin을 확인할 수 있습니다. 전체 사이트를 허용하는 `*` 대신 자신의 사이트 주소만 지정하세요.

Windows PowerShell (Ollama 트레이 앱을 먼저 종료):

```powershell
$env:OLLAMA_ORIGINS="https://your-site.example"
ollama serve
```

macOS 앱 (설정 후 앱 종료·재시작):

```sh
launchctl setenv OLLAMA_ORIGINS "https://your-site.example"
```

Linux 수동 실행:

```sh
OLLAMA_ORIGINS="https://your-site.example" ollama serve
```

Linux systemd 서비스라면 서비스 환경변수 설정으로 같은 값을 적용한 뒤 재시작합니다. 기존 서버가 실행 중이면 같은 포트에 두 번째 Ollama를 실행하지 마세요. 로컬 개발에서는 예를 들어 `http://127.0.0.1:3000`을 지정합니다.

4. 사이트에서 ‘내 LLM 연결’을 누르고 주소 `http://127.0.0.1:11434`, 모델 이름 `qwen3:8b`를 입력합니다. **연결 확인 및 저장**을 누르면 브라우저가 해당 주소의 `/api/tags`에 직접 접속하여 모델 설치 여부를 확인합니다. 목록에 있는 다른 모델 이름도 사용할 수 있습니다.
5. 브라우저가 로컬 네트워크 접근 권한을 요청하면 허용합니다. 브라우저 종류·버전·조직 정책에 따라 HTTPS 사이트의 로컬 접근이 제한될 수 있습니다. 이 경우 CORS와 로컬 네트워크 권한을 확인하거나 사용자가 접근할 수 있는 HTTPS Ollama 프록시를 구성해야 합니다. 인터넷 전체에 Ollama 포트를 공개하는 방식은 사용하지 마세요.
6. 챗봇을 선택하고 메시지를 보냅니다. Enter 전송, Shift+Enter 줄바꿈, 응답 중지·답변 복사·새 대화를 지원합니다.

`127.0.0.1`과 `localhost`는 **브라우저를 사용하는 기기 자신**입니다. PC에서 접속하면 자신의 PC Ollama를 가리킵니다. 휴대폰에서는 PC의 모델을 자동으로 찾지 않습니다. 다른 기기·서버의 모델은 접근 가능한 HTTPS 주소와 해당 서버의 사이트 접속 허용 설정이 필요합니다. HTTP 연결은 localhost/127.0.0.1만 허용하고 다른 호스트는 HTTPS만 허용합니다. 주소에 인증정보·경로·쿼리 문자열을 넣을 수 없습니다. 인증 API 키가 필요한 다른 LLM 서비스는 현재 지원하지 않습니다.

## 지침과 기능 범위

- 원문 24종을 `private/instructions/`에 보존하고 요청에 따라 1~23번을 표시합니다. DOCX의 문단 텍스트를 원래 순서로 추출했으며 문구를 수정하지 않았습니다. 서식·이미지는 포함하지 않았습니다.
- 원본 지침은 서버의 private/instructions에 보관하며 브라우저나 개인 로컬 모델에 보내지 않습니다. 이전 `/api/bots/번호/context` 경로는 원본을 반환하지 않도록 차단했습니다. 개인 모델은 별도로 작성한 공개용 일반 업무 안내만 사용합니다. 따라서 원본 GPT의 예시·세부 행동을 그대로 재현하는 구성이 아닙니다. 영어 JSON은 공개용 안내의 구조이며 암호화나 비공개 수단이 아닙니다.
- 08 종사자 고충상담, 10 평가관리는 필수 지식 PDF가 제공되지 않았으므로 전송이 차단됩니다. 현재 PDF 검색 기능은 구현되어 있지 않습니다.
- 이미지 생성, 웹검색, 캔버스, HWPX·DOCX 내보내기는 아직 없습니다. 텍스트 대화만 지원하며 없는 도구를 수행했다고 주장하지 않도록 별도 실행 안내를 추가합니다.
- 같은 지침을 전달해도 모델마다 준수도와 한국어 작성 품질이 다릅니다. 실제 기록의 사실관계·평가기준을 확인하세요.
- 모델 문맥 설정 32,768 토큰, 출력 한도 4,096 토큰, 대기 한도 180초입니다. 장비·모델의 지원 여부를 확인하세요. 최대 40개 메시지·총 60,000자·메시지당 16,000자까지 전송합니다.
- 대화는 선택한 모델 서버에 전달됩니다. 기본 PC 주소 대신 외부 HTTPS 모델 주소를 입력하면 그 서버가 대화를 받는다는 점을 확인하세요.

## 검증 결과와 한계

`npm test`의 8개 테스트는 목록·원문 해시·원본 경로 차단·PDF 미연결 차단·주소 검증·Ollama 통신·영어 JSON 공개용 안내·설정 검증·유니코드 글자 수 제한을 검증합니다. 테스트 모델을 사용하며 실제 모델 생성 품질의 검증은 아닙니다.

브라우저 검증에서는 격리된 두 브라우저가 서로 다른 테스트 모델에 연결하여 답변받는 것을 확인했습니다. 설정 저장·대화 분리·오류 시 재입력 보존·연결 해제·모바일 화면을 확인했고 공용 서버로 대화 POST가 전송되지 않는 것을 확인했습니다. 실제 사용자 PC의 Ollama, 공용 HTTPS 사이트에서의 로컬 네트워크 접근 및 외부 배포는 아직 검증되지 않았습니다.

`/health`는 웹서버 상태만 확인합니다. 사용자의 실제 Ollama 상태는 각자의 브라우저에서 연결 버튼을 통해 확인합니다.

## 대화 기록 저장 방식

브라우저 IndexedDB의 `welfare-insight-chats` 데이터베이스, `conversations` 저장소에 보관합니다. 각 기록에는 대화 ID, 챗봇 번호, 첫 메시지에서 만든 제목, 작성·수정 시각, 모델 이름, 사용자·AI 메시지가 들어갑니다. 정상적인 모델 응답을 받은 후 해당 대화를 저장하고 이후 답변마다 갱신합니다. 오류·중지된 요청과 아직 보내지 않은 입력은 기록하지 않습니다.

공용 서버에는 대화를 업로드하지 않고 해당 기기·브라우저·사이트 주소에 묶여 보관합니다. 다른 PC나 브라우저로 자동 동기화되지 않습니다. 같은 브라우저 프로필을 함께 사용하는 사람은 기록도 함께 볼 수 있습니다. 별도 앱 암호화나 계정 잠금은 없습니다. 브라우저의 사이트 데이터 삭제, 시크릿 창 종료, 저장 용량 정리 등으로 삭제될 수 있으므로 장기 보관을 보장하지 않습니다. 도메인이 바뀌면 기존 도메인 저장소에 자동 접근할 수 없습니다.

저장이 차단되거나 실패하면 화면에 경고하고 현재 접속 메모리에서만 유지합니다. ‘새 대화’는 기존 기록을 지우지 않으며, 목록의 × 삭제는 해당 기록을 실제 IndexedDB에서 삭제합니다. 연결 해제는 모델 설정만 지웁니다. 여러 탭에서 동일 대화를 동시에 수정하면 마지막 저장이 반영되므로 한 탭에서 편집하세요.

대화 기록 기능의 브라우저 테스트: `python3 test/browser-history.py` (Python Playwright와 Chromium 필요, `CHROMIUM_PATH`로 실행파일 지정 가능). IndexedDB의 새로고침 유지, 여러 대화 이어가기, 챗봇·브라우저 분리, 개별 삭제 유지, 저장소 차단 시 안내를 검증합니다.

로고 자산: `public/logo.png`는 대화에 표시된 로고를 참고해 준비한 웹용 재현 이미지입니다. 원본 PNG 바이트를 직접 복사한 파일은 아닙니다. 브랜드 로고와 파비콘에 사용하며, 원본 파일을 제공받으면 같은 경로로 교체할 수 있습니다.

## 챗봇별 출력 설정

각 챗봇 안의 ‘챗봇 설정’에서 전체 추가 지침, 출력 항목별 최대 글자 수와 추가 지침을 입력합니다. 저장한 값은 브라우저 localStorage의 `care-settings-챗봇번호`에 보관되고 다음 답변부터 적용됩니다. 새로고침해도 유지되며 챗봇마다 분리됩니다. 설정창에는 원본 지침을 표시하지 않고, 입력란은 사용자가 추가한 내용만 보여줍니다.

최대 글자 수는 1~12,000의 정수이고 비워두면 별도 제한을 적용하지 않습니다. 전체 추가 지침은 6,000자, 항목별 추가 지침은 2,000자까지 입력합니다. 공개 안내와 설정은 영어 키·영어 실행 규칙을 가진 JSON으로 구성하며, 한국어 항목 이름과 사용자 지침은 그대로 유지합니다. 모델의 응답 언어는 한국어입니다.

Ollama에 JSON 출력 스키마를 함께 전달합니다. 항목별 글자 수는 공백을 포함한 유니코드 코드포인트 수이며 제목은 제외됩니다. 제한 초과 본문은 표시·저장 전에 잘라내고 안내합니다. 잘린 문장은 부자연스러울 수 있으므로 검토하세요. 필수 정보 질문·후속 안내는 항목 본문 제한에 포함하지 않습니다. JSON 출력을 지원하고 구조를 준수하는 모델이 필요하며, 형식이 잘못되면 오류를 표시합니다.

원본 비공개는 네트워크 전송을 제거해 구현했습니다. 원본 파일이 담긴 저장소·서버 자체의 접근 권한도 관리해야 합니다. 변경 이전에 사용자가 이미 받은 원본 지침 복사본은 이 수정으로 회수할 수 없습니다.

## Vercel 배포

이 저장소에는 Node 개발 서버와 Vercel 정적 배포 설정이 함께 있습니다. Vercel의 Framework Preset은 Other, Build Command는 `npm run build`, Output Directory는 `public`, Root Directory는 저장소 루트입니다. Production Branch는 최초 커밋을 올린 `main`을 선택합니다. `vercel.json`이 빌드와 경로를 설정합니다. 웹사이트가 사용하는 `/api/bots`는 빌드된 공개 카탈로그 `/bots.json`으로 연결합니다.

비공개 `private/` 원본 지침은 Git과 Vercel 업로드에서 제외됩니다. 현재 머신에 보관된 원본은 복제된 Git 저장소나 Vercel에 자동 복원되지 않습니다. 필요하면 운영자만 접근 가능한 별도 저장소에 보관하세요. 지침이 사용되지 않는 공개용 로컬 LLM 앱은 원본 없이 실행됩니다. 원본 해시 검증 테스트는 별도 원본 파일이 없는 체크아웃에서는 명시적으로 건너뜁니다.

배포 후 각 사용자는 배포된 HTTPS 사이트 주소를 자신의 Ollama `OLLAMA_ORIGINS`에 설정하고 브라우저의 로컬 네트워크 접근을 허용해야 합니다. 실제 Vercel 배포는 빌드 테스트와 별개이며 공개 URL에서 연결 검증이 필요합니다.
